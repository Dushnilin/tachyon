# Десинхронизация пакетов и фаззер

[English](../en/07-desync-fuzzer.md) | [К оглавлению](README.md)

Для соединений, где требуется оптимизация прохождения трафика напрямую через провайдера без использования внешнего прокси-сервера, в `tachyon-core` встроен собственный движок **пакетной десинхронизации (`desync`)**. Он работает на уровне ядра в едином процессе и не требует отдельных внешних демонов.

## Назначение и область применения

Источник типа `desync` модифицирует параметры начальных TCP/TLS-пакетов (фрагментацию записи TLS, разделение заголовков ClientHello, управляемые ложные пакеты, перекрытие последовательностей и параметры UDP-сессий) таким образом, чтобы пакеты корректно доходили до целевого узла при наличии инспекции или потери целостности фрагментированных кадров на промежуточных транзитных сетевых узлах.

Типовой сценарий настройки:

1. В `Маршруты -> Узлы и подписки` добавьте источник с типом **`Desync`**.
2. В `Маршруты -> Секции маршрутизации` создайте секцию с действием **`Десинхронизация (Desync)`** и привяжите к ней нужные наборы правил `.trs` или списки доменов (или используйте пресет мастера подключения без подписки).

## Пресеты и режим Adaptive 2.0 (`auto_tune`)

Поле **`desync_preset`** задаёт базовую стратегию обработки пакетов:

- **`auto` (Adaptive 2.0)**: рекомендуется по умолчанию — автоматически подбирает параметры фрагментации и адаптируется под поведение маршрута.
- Готовые режимы: `split`, `multisplit`, `disorder`, `multi_disorder`, `fake`, `fake_split`, `fake_disorder`.
- **`custom`**: ручная настройка всех флагов или импорт строки стратегии из встроенного фаззера.

При включённом флаге **`desync_auto_tune`** (Adaptive 2.0 Auto-Learning) ядро отслеживает аномалии на потоках — преждевременный `TCP RST`, обрыв рукопожатия или деградацию скорости (`< 20 KiB/s`) — автоматически переключает стратегию на резервную и сохраняет рабочий профиль для конкретного `SNI` в локальную базу `cache.db`, чтобы при последующих обращениях соединение устанавливалось сразу.

## Ключевые параметры ручной настройки

| Параметр | Назначение |
|---|---|
| `desync_mode` | Базовый метод разбиения (`split`, `multisplit`, `disorder`, `fake` и др.) |
| `desync_split_pos` | Позиция разреза пакета: маркеры `midsld`, `sni`, `sniext+1`, `host+1`, `endhost-1`, `extlen`, смещение в байтах (`1..1400`) или список позиций через запятую (например, `1,sniext+1,midsld`) |
| `desync_tlsrec_first` | Предварительная фрагментация на уровне записи TLS (`TLS Record Split`) до отправки по TCP |
| `desync_fooling` | Метод пометки вспомогательного пакета для отсечения на промежуточном транзитном узле (`badsum`, `md5sig`, `ts` и др.) |
| `desync_fake_ttl` | Ограниченный `TTL` для вспомогательного пакета (`autottl` / числовое значение), чтобы пакет не доходил до конечного сервера |
| `desync_repeats` | Число повторов вспомогательного пакета |
| `desync_seqovl` | Перекрытие TCP sequence numbers при разбиении |
| `desync_fake_sni` / `desync_sni_pool` | SNI и пул имён для вспомогательных заголовков или `desync_fake_tls` / `desync_fake_payload` |
| `desync_wsize` / `desync_wscale` | Управление размером TCP-окна и масштабированием для снижения буферных сбросов |
| `desync_split_delay_ms` | Задержка между фрагментами (мс) |
| `desync_ipfrag` | Фрагментация на уровне IP-пакетов |
| UDP-опции | `desync_udp_fake`, `desync_udp_repeats`, `desync_udp_fake_ttl`, `desync_udp_fake_payload`, `desync_udp_out_range`, `desync_udp_keep_socket`, `desync_udplen` для QUIC и UDP-сессий |

## Встроенный фаззер стратегий

Непосредственно из модального окна настройки `desync`-источника (а также из раздела диагностики и через Telegram-команду `/fuzzer`) можно запустить **фаззер стратегий**:

- Фаззер перебирает безопасные комбинации позиций разреза, фулинга и TTL на маршрутизаторе по отношению к заданному тестовому домену.
- Найденная устойчивая стратегия применяется в один клик (автоматически переводя источник в режим `custom` и заполняя `desync_opts`).
