# Установка и миграция с 1.x

[English](../en/01-installation.md) | [К оглавлению](README.md)

## Системные требования

- **Операционная система**: OpenWrt `23.05+` или `24.10+` (с пакетным менеджером `opkg` или новым `apk`).
- **Архитектура**: `x86_64`, `i386_pentium4`, `aarch64`, `armv7`, `armv6`, `riscv64`, `mipsel`, `mips`.
- **Модули ядра**: `kmod-nft-tproxy` (режим TProxy по умолчанию), `kmod-tun` (при использовании режима TUN), пакет `nftables` (`fw4`).
- **Память**:
  - RAM: рекомендуется от 256 МБ для базовых сценариев и от 512 МБ при подключении крупных наборов правил и нескольких подписок.
  - Flash: не менее 25–40 МБ свободного пространства во внутреннем разделе overlay (или вынесенный каталог кэша на внешний накопитель).
- **Сетевые утилиты для установщика**: `curl` или `wget`.

> [!NOTE]
> Движок `tachyon-core` является единственным штатным ядром маршрутизации в версии 2.0. Устаревшие сторонние движки (`sing-box`, `zapret`, `byedpi`) в 2.0 не используются и при обновлении удаляются.

## Быстрая установка через `install.sh`

Выполните скрипт установки от имени `root` через SSH:

```sh
sh -c "$(curl -fsSL https://raw.githubusercontent.com/Dushnilin/tachyon/2.0/install.sh)" -- -y
```

Чтобы протестировать предварительные релизные сборки (`beta` / `rc`), укажите флаг канала:

```sh
sh -c "$(curl -fsSL https://raw.githubusercontent.com/Dushnilin/tachyon/2.0/install.sh)" -- -y --channel beta
```

### Полный список параметров `install.sh`

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-y`, `--yes` | выкл. | Автоматическое подтверждение установки без интерактивных вопросов |
| `-n`, `--dry-run` | выкл. | Проверка доступности релиза и вывод плана действий без изменений на маршрутизаторе |
| `-q`, `--quiet` | выкл. | Скрытие информационных сообщений |
| `--channel <CH>` | `auto` | Канал релизов: `auto`, `stable` или `beta` (включая `rc`) |
| `--prerelease` | выкл. | Включить предварительные сборки (`beta` и `rc`), псевдоним для `--channel beta` |
| `--tag <VERSION>` | — | Установка точного тега, например `--tag v2.0.0-rc.1` или `--tag v2.0.0` |
| `--format <FMT>` | `auto` | Формат пакета: `auto`, `apk` или `ipk` |
| `--arch <ARCH>` | автоопределение | Принудительный выбор целевой архитектуры (`x86_64`, `aarch64`, `armv7`, `mipsel` и др.) |
| `--reinstall` | выкл. | Принудительная переустановка пакета поверх установленных файлов |
| `--repair` | выкл. | Восстановление служб, скриптов инициализации и файлов пакета на месте |
| `--tachyon-core` | совместимость | Флаг совместимости (`tachyon-core` устанавливается как штатное ядро) |
| `--repo <OWNER/REPO>` | `Dushnilin/tachyon` | Альтернативный GitHub-репозиторий с релизами |
| `--skip-core` | выкл. | Пропустить загрузку и обновление бинарника `tachyon-core` |
| `-h`, `--help` | — | Вывод справки по параметрам |

Журнал установки сохраняется на роутере в `/tmp/tachyon-install.log`.

## Миграция с Tachyon 1.x на 2.0

При установке версии 2.0 поверх Tachyon 1.x установщик и сервис автоматически переносят конфигурацию из старого UCI (`/etc/config/tachyon`) в новое JSON-хранилище `/etc/tachyon/tachyon.json`:

1. Исходный файл `/etc/config/tachyon` не перезаписывается деструктивно — создаётся резервная копия.
2. Переносятся секции маршрутизации, условия трафика, пулы исходящих подключений, балансировщики, профили, расписания, гостевой режим, входящие серверы и параметры Telegram-бота.
3. Устаревшие поля подписок и ссылки на формат `.srs` для встроенных правил переводятся на `.trs` там, где это безопасно; пользовательские сторонние `.srs`-ссылки сохраняются.

При необходимости повторный импорт можно запустить вручную из терминала:

```sh
tachyon import-legacy
```

Для проверки корректности сгенерированной конфигурации после переноса выполните:

```sh
tachyon config_plan
tachyon status
```

## Политика релизов и каналы обновлений

Проекты семейства Tachyon придерживаются последовательного цикла публикаций:

1. **`beta`** — первичная публикация новых функций и изменений архитектуры.
2. **`rc` (Release Candidate)** — заморозка функциональности и проверка стабильности перед основным релизом.
3. **`stable`** — основной выпуск после успешной обкатки пре-релизов.

Подробное переключение канала обновлений (`auto`, `stable`, `beta` с включением `rc`) в веб-интерфейсе описано в разделе [Обновления, каналы и системные настройки](11-updates-settings.md).

## Удаление

Для корректного удаления пакета с сохранением резервной копии настроек в `/etc/tachyon-backup-<timestamp>`:

```sh
sh -c "$(curl -fsSL https://raw.githubusercontent.com/Dushnilin/tachyon/2.0/uninstall.sh)" -- -y
```

Дополнительные ключи `uninstall.sh`:

- `-p`, `--purge` — удалить все файлы конфигурации, журналы состояния и резервные копии без создания бэкапа.
- `--keep-binaries` — оставить `/usr/bin/tachyon-core` на диске.
