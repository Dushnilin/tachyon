# Проверка IP/DNS и режим Plus

Окно открывается во вкладке «Диагностика» кнопкой «Проверка утечек IP и DNS». Галочка «Режим Plus» находится под описанием; её состояние сохраняется в браузере. После смены режима нужно повторить проверку. Во время выполнения галочка заблокирована. Настройки DNS и маршрутизации тест не меняет.

## Исправления обычного режима

Ответ bash.ws содержит разные типы записей: `ip` — внешний IP клиента, `dns` — резолвер, `conclusion` — заключение сервиса. В таблицу должны попадать только `dns` с валидным IPv4/IPv6. Иначе IP клиента и строка `DNS may be leaking.` ошибочно становятся DNS-серверами; совпадение строки в Direct/Proxy даёт ложное предупреждение.

Исправления применяются в обоих режимах. Повторы удаляются, настроенные WAN DNS больше не подставляются вместо отсутствующих наблюдений. Совпадение адреса в Direct и Proxy само по себе означает `shared`, а не принадлежность провайдеру. Известные публичные DNS отмечаются как публичные; неизвестные и общие резолверы — «Не подтверждено». Публичная принадлежность не доказывает шифрование.

Совпадение с DNS-адресом из конфигурации WAN — предупреждение, требующее оценки ожидаемой политики. При выборочной маршрутизации оно не доказывает утечку всех запросов. Поле `dns_leaked` сохраняет совместимость с предыдущим API и не является гарантией проверки каждого клиента.

## Сравнение режимов

| Проверка | Обычный | Plus |
|---|---|---|
| Публичный IP через WAN и локальный HTTP proxy | Да | Да |
| Резолверы HTTP-проб Direct/Proxy | Да | Да |
| Фильтрация типов записей и осторожная классификация | Да | Да |
| Отдельные уникальные запросы через DNS роутера `127.0.0.1` | Нет | Да |
| Наблюдение открытого DNS тестовых имён на выбранном WAN | Нет | Да, при наличии tcpdump |
| Реальный DNS-запрос к активному DoH endpoint с проверкой TLS | Нет | Да, для `dns-server` типа `https` |
| Протокол и явный detour из sing-box-конфига | Нет | Да |
| Проверка всех приложений, интерфейсов и фактического TLS движка | Нет | Нет |

Plus выполняет дополнительные запросы и занимает больше времени. Выключение Plus не отменяет общие исправления и не возвращает неизменённую старую реализацию.

## Что подтверждают новые пробы

**DNS роутера:** отдельный идентификатор bash.ws и четыре уникальных имени через `dig @127.0.0.1` уменьшают влияние кэша. Наблюдения показываются отдельно от HTTP-проб, маршрут которых не доказывает DNS-маршрут.

**Открытый DNS на WAN:** ограниченный по времени tcpdump наблюдает исходящий TCP/UDP на порту 53 выбранного WAN, включая IPv4/IPv6. Сохраняются только строки, содержащие уникальные имена этого запуска; PCAP и DNS других пользователей не сохраняются. Обнаружение тестового имени подтверждает незашифрованный запрос в указанной области проверки. При отсутствии инструмента, ошибке запуска, потере пакетов, незавершённом захвате или отсутствии наблюдений DNS результат не считается успешной отрицательной проверкой. Отсутствие открытых запросов на этом интерфейсе не доказывает отсутствие утечек на других интерфейсах или портах.

**DoH/TLS:** независимый curl-запрос к активному `dns-server` получает DNS wire response через HTTPS. Успех требует успешного TLS с проверкой сертификата, HTTP 200, DNS Content-Type и корректного DNS-ответа на исходный вопрос. HTTP 200 или успешный handshake без DNS-ответа недостаточны. DoH-профиль и путь не попадают в аргументы процесса или результаты; временные файлы удаляются. `tls.insecure` в конфигурации движка показывается отдельным предупреждением и не изменяется тестом.

Эта проба проверяет собственное соединение curl к endpoint с обычной маршрутизацией роутера. Она не подтверждает TLS соединения sing-box и не воспроизводит его detour. DoT/DoQ/H3 или другой активный движок не следует считать проверенными этой DoH-пробой. Протоколы ниже в окне берутся из сгенерированного `/etc/sing-box/config.json`, а не из захвата расшифрованного трафика.

Неизвестная классификация, недоступная или неполная проба не превращаются в обещание «всё безопасно». Bootstrap UDP сам по себе не доказывает утечку пользовательских запросов; Secure DNS браузера и остальные приложения могут использовать отдельные резолверы.

## Зависимости и CLI

Для расширенного захвата нужен необязательный `tcpdump` (в OpenWrt доступен пакет `tcpdump-mini`). При его отсутствии обычный режим и остальные пробы Plus работают, а отсутствие захвата показывается явно. `dig`, curl и timeout уже входят в зависимости Tachyon.

```sh
tachyon leak_check
tachyon leak_check plus
tachyon leak_check plus --pretty
tachyon leak_check_async plus
tachyon leak_check_status JOB_ID
```

Обычный CLI/API остаётся совместимым; `plus` — необязательный аргумент. Результаты Plus включают `router_dns_servers`, `router_dns_status`, `configured_dns`, `wan_dns_capture` и `doh_tls_probe`.

## Проверки

`tests/leak_check_plus.sh` проверяет фильтрацию ответа, классификацию, IPv4/IPv6 наблюдения, потери/незавершённый захват, TLS-ошибки, неправильный Content-Type и DNS-ответ, исключение приватных путей и очистку временных файлов. Frontend-тесты проверяют передачу режима, восстановление предпочтения, предупреждения и границы положительных результатов. Существующие тесты не ослабляются.
