# Подписка на серверные подключения

В LuCI → Tachyon → Серверы кнопка **«Настроить подписку»** расположена над
описанием входящих подключений. Она открывает настройки публикации списка
клиентских URI. Изменения ядра и отдельный VPN-процесс не требуются.

## Настройка

1. Включить подписку, указать публичный хост, схему и порт HTTP-сервиса.
2. Выбрать все включённые серверы либо явный список. В режиме «все» новые
   включённые серверы автоматически появятся при следующем обновлении клиента.
3. Скопировать URL или показать QR-код. По умолчанию ответ — Base64 от списка
   URI по одному в строке; доступен также текстовый формат.
4. Сохранить окно и выполнить **Save & Apply** на основной странице. До этого
   работает предыдущая сохранённая конфигурация. Сохранение окна не применяет
   остальные ожидающие UCI-изменения автоматически.

«Сменить ссылку подписки» создаёт новый 256-битный токен через Web Crypto.
После Save & Apply старый URL возвращает 404. При отсутствии криптографического
генератора настройка отказывается создавать слабый токен.

## Публикация и доступ

Пакет устанавливает `/www/cgi-bin/tachyon-sub`, обслуживаемый существующим
uhttpd. Запрос не требует LuCI-сессии: отдельный токен обязателен для каждой
выдачи. Пока подписка не включена, обработчик отвечает 404.

```text
https://vpn.example.com/cgi-bin/tachyon-sub/TOKEN?format=base64
```

Указанный хост и порт описывают уже доступный адрес обработчика. Эта форма не
создаёт TLS-сертификаты, reverse proxy или правила WAN. Для использования вне
LAN нужен действующий HTTPS-сертификат и публикация именно пути подписки.
Не следует ради этого открывать всю LuCI: можно проксировать только
`/cgi-bin/tachyon-sub/` на закрытый HTTP-сервис роутера и отклонять остальные
пути. HTTP полезен для проверки внутри доверенной сети.

### Прямой HTTPS на роутере

Без reverse proxy можно настроить отдельный instance uhttpd со свободным
портом и docroot, содержащим только обработчик подписки. Существующие
listeners LuCI и пробросы портов сохраняются. Пример ниже использует порт
8443 и предварительно выпущенный сертификат для `vpn.example.com`.

Создать `/www/tachyon-subscription/cgi-bin/tachyon-sub` с правами 0755:

```sh
#!/bin/sh
exec /www/cgi-bin/tachyon-sub
```

Добавить отдельную секцию в `/etc/config/uhttpd`, адаптировав пути сертификата:

```uci
config uhttpd 'tachyon_subscription'
    list listen_https '0.0.0.0:8443'
    option home '/www/tachyon-subscription'
    option cgi_prefix '/cgi-bin'
    option cert '/etc/ssl/acme/vpn.example.com.fullchain.crt'
    option key '/etc/ssl/acme/vpn.example.com.key'
    option no_dirlists '1'
    option no_symlinks '1'
    option max_requests '3'
    option max_connections '32'
    option script_timeout '20'
    option network_timeout '20'
```

В этом instance не добавлять LuCI, Lua/ucode prefixes или ubus prefix и не
использовать основной `/www` как docroot. Для доступа извне отдельно разрешить
выбранный TCP-порт во входящей WAN-зоне и проверить firewall. На роутере
применить настройки uhttpd штатно. В окне подписки указать тот же домен,
HTTPS и порт 8443. Реквизиты серверов не меняются; сертификатные ключи и токен
подписки не должны находиться в docroot.

Настроить штатное ACME-продление и перечитывание сертификата uhttpd после
обновления. Проверить доступ из внешней сети с обычной проверкой TLS:
правильный токен возвращает 200, неправильный — 404, `/cgi-bin/luci` и
`/ubus` не должны открываться. Не включать журналирование URL с токенами.

Токен даёт доступ к реквизитам всех выбранных серверов. Не включать его или
тела ответов в access logs, аналитику, публичную документацию и отчёты.
Ответы имеют `Cache-Control: no-store`, `Referrer-Policy: no-referrer` и
`X-Content-Type-Options: nosniff`. Поддерживаются GET и HEAD. Неверный токен
не запускает чтение сертификатов или генерацию URI.

## Состав

Поддерживаются URL VLESS, VMess, Trojan, Shadowsocks, SOCKS, HTTP/Mixed,
Hysteria2, TUIC, AnyTLS, Naive, ShadowTLS, FPTN и MTProto. Mieru распознаётся
в JSON Inbound с `type: "mieru"`, полями `listen_port`, `transport` и
`users[0].name/password`. Для обычных серверов используется основная identity,
как в существующем окне информации сервера, а не все учётные записи.

Tailscale, AWG (выдаёт отдельный конфиг) и неизвестные JSON-типы не имеют
поддерживаемого URI подписки; окно показывает «Нет ссылки для подписки».
Выключенные серверы пропускаются. Пустой явный список не превращается во все
серверы. Если экспортировать нечего, авторизованный запрос получает 422.

Обработчик читает сохранённую UCI при каждом запросе. `public_host` каждого
сервера имеет приоритет; при его отсутствии используется хост подписки.
Настройки TLS, Reality, транспорта, обфускации и сертификатные пины входят
в URI соответствующих протоколов. Генератор не меняет реквизиты, маршрутизацию
или JSON ядра и не вызывает reload.

## UCI и реализация

Поля секции `tachyon.settings`:

| Поле | Значение |
|---|---|
| `server_subscription_enabled` | `1` включает выдачу, отсутствие выключает |
| `server_subscription_host` | Домен, IPv4 или IPv6 адреса подписки |
| `server_subscription_scheme` / `server_subscription_port` | Схема и порт ссылки, по умолчанию HTTPS/443 |
| `server_subscription_format` | `base64` или `plain` |
| `server_subscription_mode` | `all` или `selected` |
| `server_subscription_servers` | UCI list идентификаторов серверов |
| `server_subscription_token` | 64 строчных hex-символа, секрет |

Генератор: `server/links.uc`; выдача и фильтрация: `server/subscription.uc`.
UI использует штатную UCI-модель основной формы, поэтому ожидающие изменения
сохраняются и применяются обычным путём. Сохранение окна вызывает `uci.save()`
без parse остальных вкладок, чтобы не записывать их значения по умолчанию.
Backend не записывает конфигурацию.

## Проверки

- `bash tests/server_subscription.sh`: формат URI, UTF-8 и IPv6, выбор серверов,
  отключение и смена токена, отказ без авторизации, параметры TLS и CGI-ответы
  на вымышленной UCI-базе.
- `npm test -- --run`: в том числе `serverSubscription.test.js` с проверкой
  URL/токена, поддерживаемых серверов и расположения кнопки.
- Frontend lint/build, `tests/ci_guards.sh`, существующие контракты формы серверов.

Поддержка URI в подписке не добавляет поддержку протокола конкретному клиенту.
Импорт и обновление нужно проверить в выбранном приложении и из нужной сети.
